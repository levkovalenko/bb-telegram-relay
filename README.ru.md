# bb-telegram-relay

Мульти-пользовательский Telegram-релей для оповещений команды — плагин BB
(id `telegram-relay`, пакет `bb-plugin-telegram-relay`).

Существующий Telegram-бот (исходящий HTTPS long polling, без webhook и
портов) принимает команды участников; каналы и подписки хранятся в собственном
SQLite-хранилище плагина. Веха M1 — каркас: polling-сервис, хранилище,
команды бота, управление владельцем (`/admin` в боте и `bb telegram-relay`
в CLI), тексты бота RU/EN и заглушка панели. Веха M2 — broadcast-доставка
с append-only журналом рассылок. Панель управления и e2e-сценарий
мониторинга — вехи M3–M4.

## Команды бота

| Команда | Кто | Действие |
| --- | --- | --- |
| `/start` | все | Подписка на канал по умолчанию (создаётся `general`, если каналов нет) + приветствие на языке пользователя (RU/EN). |
| `/channels` | все | Inline-клавиатура каналов; тап = подписка / отписка. |
| `/help` | все | Краткая справка. |
| `/admin list` | владелец | Список каналов с числом подписчиков. |
| `/admin create <id> [название…]` | владелец | Создание канала (id — строчный slug). |
| `/admin setdefault <id>` | владелец | Канал по умолчанию для `/start`. |
| `/admin delete <id>` | владелец | Удаление канала вместе с подписками. |
| `/admin subs [канал]` | владелец | Список подписчиков (все или по каналу). |

## Broadcast-доставка (M2)

Автотаски и агенты шлют оповещения через CLI или RPC плагина (тот же
контракт):

```
bb telegram-relay broadcast --title <t> --body <b> --channels <c1,c2> [--level info|warning|critical]
bb telegram-relay deliveries [limit]        # последние рассылки, только метаданные
```

RPC: `broadcast({ title, body, channels, level? })` → `{ logId, sent,
failed }` и `listDeliveries({ limit? })` (вход для журнала в M3).

Поведение:

- Получатели — уникальные chat_id, подписанные на любой из перечисленных
  каналов; каждому чату сообщение приходит один раз. Неизвестный id канала —
  ошибка.
- Глобальный темп ~30 msg/s; HTTP 429 — ожидание `retry_after` от API и
  повторная отправка.
- Ошибка разбора Markdown (400) повторно шлётся plain-текстом и считается
  доставленной.
- Сбой у одного получателя (403 blocked, 400, сеть) логируется и никогда не
  прерывает доставку остальным.
- После 3 подряд неудач для chat_id его подписки удаляются автоматически
  (лог "auto-unsubscribed"); успешная доставка сбрасывает счётчик. Чисто
  сетевые ошибки засчитываются в серию, но не вызывают отписку (отключение
  сети не должно отписывать всех).

Каждая рассылка добавляет строку в журнал `delivery_log` (хранятся 1000
последних): id каналов, заголовок, level, счётчики sent/failed и метаданные
ошибок по получателям `{ chat_id, code, description }`. Тела сообщений никуда
не пишутся.

## Настройки

| Ключ | Тип | Примечание |
| --- | --- | --- |
| `botToken` | **secret** (строка) | Токен бота от @BotFather. Хранит bb в 0600-файле секретов: никогда не попадает в базу, во фронтенд и в логи. Устанавливается после установки плагина: `bb plugin config telegram-relay set botToken <токен>`. |
| `ownerChatId` | число | Числовой Telegram chat id владельца; только этот чат может использовать `/admin`. |
| `enabled` | boolean, по умолчанию `true` | Включает long polling. |
| `pollTimeout` | число, по умолчанию `10` | Ожидание long-poll каждого `getUpdates`, 1–30 с. |

Без токена плагин в статусе **needs-configuration** (без crash-loop);
установка значения запускает повторную загрузку. Poller перечитывает
настройки на каждой итерации — `enabled` и `pollTimeout` применяются без
перезагрузки.

## Приватность и секрет

- Токен пишется **только** в secret-настройку плагина; в исходники,
  репозиторий, тесты, логи и фронтенд он не попадает.
- Логи содержат только метаданные: chat_id, команда, результат. Текст
  сообщений, имена пользователей и токен в логи не пишутся.

## Надёжность

- Дедупликация `getUpdates` по `update_id`; зафиксированный offset
  сохраняется в KV плагина — после рестарта обновления не дублируются.
- Сетевые ошибки: экспоненциальный бэкофф (1 с → 60 с).
- HTTP 429: ожидание `retry_after` от API.
- HTTP 409 (токен опрашивает другой потребитель): poller пишет в лог и
  gracefully останавливается (статус `conflict`) вместо crash-loop.
  Остановите другого потребителя и выполните
  `bb plugin reload telegram-relay`.

## Разработка

```bash
npm install
npm run typecheck   # tsc --noEmit
npm run build       # bb plugin build
npm test            # node --test test/ (на собранный dist/server.js)
bb plugin install . # затем: bb plugin config telegram-relay set botToken <токен>
```

Тесты гоняют собранный серверный бандл через официальный fake plugin host
(`@get-bb/plugin-sdk/testing`, реальный временный SQLite), Telegram API
замокнут fetch-стабом: без сети и без токена.
